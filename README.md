# 光鸭网盘清理与解散工具

基于 Vue 3、TypeScript 和 `vite-plugin-monkey` 的光鸭网盘 userscript，当前实现：

- **清理文件**：按后缀、文件类型、文件名关键词、目录名关键词、最大大小、包含/完整匹配、大小写和正则进行预扫描；支持把当前规则保存为默认，并可选择是否同时记住递归设置；由用户最终勾选后分批移入回收站。
- **解散子目录**：递归扫描选中目录；重名处理可选择“保留不处理（安全，默认）”、“按光鸭网盘默认操作”（通常自动追加 `(1)`、`(2)` 等）或“回收候选重名文件”；重新扫描确认无文件后，才把对应空目录移入回收站。
- **批量重命名**：对当前选中的文件和目录执行普通/正则替换、前后缀、递增序号及逐项编辑；默认保留文件扩展名，支持跳过冲突或自动追加 `(1)`、`(2)`，并可安全处理名称互换。
- **请求速度与账号保护**：清理、解散和重命名均可选择自动/保守/均衡/快速；可启用全局默认，也可为本次操作单独覆盖。自动模式会根据 EWMA 延迟和健康响应在保守至快速范围升降；共享调度器使用账号全局下限与 read/write/poll 分通道节奏，并在 429/请求频繁时立即降档退避。

不实现 SHA1 清理，不调用清空回收站或永久删除。

## 安装

```bash
npm install
npm run build
```

然后在 Tampermonkey 或 Violentmonkey 中安装：

```text
dist/guangya-tools.user.js
```

打开 `https://www.guangyapan.com/#/home/all` 并登录。脚本会在光鸭原生工具栏旁显示“清理文件”、“解散子目录”和“批量重命名”。

## 安全行为

- 在 `document-start` 捕获页面发往 `api.guangyapan.com` 的最新鉴权上下文；不会把 token 输出到日志或 UI。
- 所有会修改文件或清除配置的操作均使用脚本自定义确认弹框；危险操作显示红色确认按钮并默认聚焦“取消”，也可按 ESC 或点击遮罩安全退出。
- 所有移动和删除固定最多 50 项一批；解散移动先按来源父目录分组。对名称和来源均可证明独立的移动，均衡/快速可保留最多 2/3 个已接受任务，但 write fetch 仍始终单并发；取消或未知结果会关闭新提交并排空所有已接受任务。
- 普通读取最多 4 并发、写入始终单并发、任务轮询单独保留公平通道，总活跃请求不超过 5；所有档位都不能关闭这些硬保护。
- 只有目录列表和任务状态等幂等读取会做有上限重试。移动、删除和重命名绝不自动重放；网络中断、坏响应、缺少任务 ID 或轮询超时导致结果未知时，会停止后续依赖操作并要求刷新确认。
- 请求调度器识别 `Retry-After`、HTTP 429、请求频繁提示和暂时性 5xx，使用带抖动退避并在成功后渐进恢复；任何运行时状态都不能突破读取 4、写入 1、轮询 1、总 fetch 5、全局启动间隔 120ms 的硬限制。
- 清理/解散的预扫描会显示进度条、百分比、当前页/目录和累计项目数；递归扫描时已发现目录总数会动态增长。
- 解散预检查保存当前面板内存快照；开始执行前再做一次完整一致性 pass。名称、父目录、类型或拓扑漂移会刷新预览且本次不写入。最终目录回收仍要求 Pass A/B 两次完整顺序分页树验证完全一致。
- 点击“开始解散”后会区分快照复核、移动提交/终态、稳定判空和目录回收进度。服务端没有条件删除接口，因此其他客户端恰好在 Pass B 后写入的 TOCTOU 风险无法彻底消除；脚本会尽量立即排队删除并在任何已知不确定性下保留目录。
- 清理默认规则保存在 userscript 的 GM 存储中，跨目录自动加载；可恢复已保存默认或清除保存并恢复内置 `txt` 规则。保存时由用户决定是否同时保存“包含全部子目录”设置。
- 清理前显示结果表，只有用户最终勾选的项目会被处理。
- 批量重命名只处理当前选中项；执行前实时预览并复刻光鸭原生名称校验（255 字符、非法字符、保留名、点号边界等）。
- 重命名冲突可选择跳过，或在扩展名前自动追加 `(1)`、`(2)`；名称互换/循环使用临时名称中转，循环失败时会逆序尝试回滚并显示残留风险。
- 重名策略默认是安全跳过：目标目录已有同名文件/目录时跳过；候选文件之间重名时移动第 1 个、跳过后续同名项。也可选择交给光鸭默认处理，由服务端通常追加 `(1)`、`(2)` 等；最终行为以光鸭服务端为准。
- 第三种“回收候选重名文件”只回收子目录里的候选重名文件，不处理目标目录中原有同名文件；候选文件原来的直接父目录仅在复扫确认没有其他文件后才回收。
- 并发分页带完整性元数据和硬终止上限；用于删除判空时会顺序复扫并要求连续两次完整结果一致。不完整、不稳定或未知 listing 一律保留目录。
- 存在未移动文件、删除失败或扫描失败时，对应非空/不确定目录会保留。
- 取消会中断排队、退避和未提交请求；写入一旦开始会等待响应，已经取得任务 ID 的服务端任务仍会在独立生命周期中等待终态。
- SPA 目录变化会关闭面板并取消后续操作。
- 解散结果会按目录展开显示冲突文件、保留目录和失败批次错误；可点击“复制失败/保留详情”生成诊断文本。

## 验证

```bash
npm test       # 核心规则和批处理测试
npm run build  # 类型检查并生成 userscript
```

模拟基准使用 20 页、每页 100ms 响应：串行理论耗时 2000ms；快速档有界并发耗时不超过 600ms，请求数仍为 20，峰值并发为 4。500 个一页子目录（根目录也按 50 项真实分页）的单次一致性 pass 固定请求数为 510；50ms 模拟延迟下四档基线约为保守 270.1s、均衡 129.4s、快速 80.7s、自动 82.1s，双 Pass 为 1020 次读取。另用 500 个独立 committed 移动任务验证窗口 1/3 的墙钟差异、drain-all 和峰值约束。所有基准均为 fake timers/mock API，不使用真实账号做压力测试。

真实接口已在隔离的临时目录中验证：分页列表、跨域鉴权复用、移动任务、任务轮询、普通删除进入回收站。测试临时目录只进入回收站，没有永久删除。
